# 매출올려드림 AI (베타)

음식점·카페 사장님이 **상호명과 주소**를 입력하면 AI(Claude)가 인터넷에 공개된 가게 정보를 찾고,
사장님이 "우리 가게가 맞다"고 확인하면 **가게 상황과 가장 큰 고민에 맞춘 인터뷰**를 진행하는 웹서비스입니다.

- 공개 주소: https://www.kkumsu.com
- 이전 버전(질문 126개 + 규칙 기반 보고서)은 GitHub 브랜치 `archive/maechul-rules-v1-20261108` 에 보관되어 있습니다.

## 화면 흐름

1. **첫 화면**: 상호명·주소 입력
2. **AI 가게 찾기** (`POST /api/store-search`): Claude가 웹 검색(최대 3회)으로 주소·업종·개업 연도·층·영업시간·판매 방식(홀/포장/배달/예약)·메뉴·평점·리뷰 경향(맛·가격·양·대기·친절·위생·화장실·주차)·온라인 채널을 정리하고, 참고한 출처를 함께 돌려줍니다.
3. **맞는지 확인**: 후보가 여러 곳이면 카드마다 선택. 못 찾으면 `정보 없이 인터뷰하기`.
4. **가게 인터뷰**: 아래 설계 원칙에 따라 질문이 달라지고, 단계(화면)별로 묶어서 보여줍니다.
5. **완료**: 답변에 따라 **맞춤 솔루션**(★★★ 우선 개선 · ★★ 이번 주 실행 · ★ 조건부 실험)과 답변 전체 요약을 보여줍니다.
   답변은 브라우저(localStorage)에 저장합니다.
6. **AI 진단 보고서**: 사장님이 동의 체크를 한 경우에만 만듭니다. 두 단계로 진행합니다.
   - **① 인터넷 조사** (`POST /api/research`): Claude가 상호명·주소로 직접 웹 검색(최대 6번)을 하고, 자동 수집이 허용된 블로그·리뷰 사이트 글(네이버 블로그·다이닝코드·식신)은 직접 열어 읽습니다(최대 5개). 플랫폼별 평점·리뷰 수(카카오맵·네이버 플레이스·구글 지도·다이닝코드 등), 리뷰 주제(맛·가격·양·대기·친절·위생·화장실·주차·분위기·메뉴)별 경향·언급 수·반복 여부, 공개 메뉴 가격, 플랫폼마다 다른 정보, 주변 경쟁점·상권, 협찬 글 비중, 분석 기간·읽은 글 수·출처(설계 문서 8장)를 정리합니다. 인터뷰 답변은 보내지 않고, 같은 가게는 3일 동안 저장한 결과를 씁니다.
   - 카카오맵·네이버 플레이스·구글 지도는 robots.txt로 자동 수집을 막고 있어 페이지를 열지 않습니다. 검색 결과나 다른 글에 나온 숫자만 출처와 함께 쓰고, 못 본 것은 '확인 못 함'으로 표시합니다. 대신 사장님이 우리 가게 평점·리뷰를 **붙여 넣는 칸(선택)** 이 있습니다.
   - **② 보고서** (`POST /api/report`): 조사 결과 + 답변 + 서버 계산값 + 붙여 넣은 리뷰를 합쳐 Claude가 운영 설계 문서 17·18장 형식으로 보고서를 만듭니다. '인터넷에서 본 우리 가게'(플랫폼별 확인 내용, 후기에서 나온 이야기, 지켜야 할 강점, 사장님 답변과 다른 점, 플랫폼마다 다른 정보, 상권·경쟁점, 확인하지 못한 것, 출처)를 함께 보여 줍니다.
   - 핵심 진단: 한 줄 진단, 상황 유형(유입 부족·고객 불편 반복·팔아도 남지 않음), 핵심 수치, 가장 중요한 문제와 근거, 지금 바로 할 일, 위생·안전 즉시 조치
   - 숫자로 본 우리 가게: **숫자는 AI가 아니라 서버가 계산**(`lib/report-calc.mjs`) — 추정 영업이익, 사장님 노동비(2026년 최저임금 10,320원 기준)를 반영한 이익, 매출 대비 비용 비율, 메뉴별 매출·1개당 남는 금액, 배달 1건 남는 금액. 배달 수수료 이중 차감·재고 기록 없음·현금 흐름 미계산을 따로 알려 줌. 참고 통계: 농림축산식품부 2025 외식업체 경영실태 조사(2024년 실적).
   - 연결 분석(수익 구조·메뉴·고객 경험), 우선 개선안 4~6개(발견한 문제·확인 근거[답변/계산/공개 정보/참고 통계/추정]·실행 방법·담당·비용과 기간·준비물·확인 지표), 실행 계획(이번 주·2~3주 차·한 달 안·마케팅·예산·성과 확인), 추가 확인할 것
   - 인쇄·PDF 저장 지원. 답변이 바뀌면 이전 보고서에 '답변이 바뀌었어요' 표시.
   - 결제와 무료/유료 구분은 아직 없습니다(베타에서는 전체 공개).

## 인터뷰 설계 원칙 (운영 설계 문서 기준)

| 원칙 | 구현 |
| --- | --- |
| 모든 사장님에게 같은 질문을 전부 묻지 않는다 | 기본 질문 + 가장 큰 고민(새 손님·이익·재방문·일손)별 추가 질문 + AI가 찾은 리뷰 신호별 카드 1개 |
| 대표 메뉴 이름을 이후 질문에 쓴다 | 예: "대표 메뉴가 얼큰 소고기국밥이네요. 이 메뉴 한 그릇을 만들 때…" (조사 자동 처리) |
| 배달을 하지 않으면 배달 질문을 건너뛴다 | 홀·포장·배달 운영 여부로 배달 단가·배달 문제·배달 매출 기준 질문을 켜고 끔 |
| 비용을 모르면 기록 방법을 안내한다 | "잘 모르겠어요" → ★★★ 비용 기록 안내 + 세부 비용 질문 생략, 알면 세부 비용·채널별 매출로 |
| 이미 확인한 정보는 다시 입력하지 않게 한다 | AI가 찾은 업종·운영 기간·채널·판매 방식·메뉴·층·리뷰 내용을 미리 채움 ("AI가 미리 채움" 표시) |
| 잘 모름·대략 입력·해당 없음 | 질문마다 필요한 상태 버튼 제공 (대략으로 답하면 요약에 "(대략)" 표시) |

- 질문 은행: `public/questions.js` (설계 문서의 질문 약 86개 + 사장님 추가 기준을 카드 51개로 묶음). 보통 한 가게당 **26~35개 카드**, 7~10단계.
- 홀이 있는 가게는 모두: **기본 서비스**(담요·앞치마·머리끈 등 준비, 자주 요청하는 물품, 춥다·덥다, 짐 둘 곳)와 **손님 앞 기본**(사장님·직원 식사 시간·장소, 식사 중 손님과 마주침, 손님 있을 때 청소)을 묻습니다.
- 홀이 있는 음식점은 모두: **반찬이 나가는 방식**과 **잔반**(최근 기억, 치울 때 살펴보기, 같은 잔반 반복, 이유, 손님에게 물어보기, 직접 맛보기)을 묻습니다.
- 단계: 가게 기본 정보 → 목표와 매출·비용 → 대표 메뉴 → {대표 메뉴} 자세히 → (식재료 구매) → (마케팅과 SNS) → 리뷰와 손님 경험 → (청소와 화장실) → (운영·배달·직원) → 실행 준비
- 리뷰 신호: 대기 → 기다리는 단계, 가격 → 가격 카드, 화장실 → 거울·조명, 위생 → 청소 루틴, 좌석 → 고객 편의, 응대 → 리뷰 관리, 입구·주차 → 입구 안내, 맛 편차 → 레시피 표준화

## 구조

```
api/store-search.js   가게 찾기 (Claude + openrouter:web_search 서버 도구)
api/research.js       보고서용 인터넷 조사 (Claude + openrouter:web_search + openrouter:web_fetch, 허용된 사이트만 열기)
api/report.js         AI 진단 보고서 (동의 후 받은 답변 + 서버 계산값 + 인터넷 조사 결과 → Claude)
lib/ai.mjs            OpenRouter 호출, JSON 꺼내기, 비용 계산
lib/guard.mjs         같은 사이트 요청만 허용, AI 비용 기록(제한은 기본 없음, 환경변수로 켤 수 있음), 결과 캐시·중복 요청 잠금(Upstash Redis)
lib/prompts.mjs       Claude 지시문과 응답 형식(JSON Schema)
lib/validate.mjs      입력 검사, AI 응답 정리(빈 값·링크·길이·리뷰 주제)
lib/mock.mjs          로컬 점검용 모의 응답 (MOCK_AI=1, 운영 배포에서는 꺼짐)
lib/research.mjs      인터넷 조사 지시문·도구 설정·결과 정리(플랫폼·리뷰 주제·출처)
lib/report.mjs        보고서 지시문·응답 형식·입력 검사(보이는 질문의 답만)·결과 정리
lib/report-calc.mjs   보고서 숫자 계산 (매출·비용·세 가지 이익·메뉴·배달 1건·참고 통계)
public/questions.js   인터뷰 질문 은행과 분기 규칙 (브라우저에서 실행, AI 비용 없음)
public/solutions.js   답변에 따른 맞춤 솔루션 (발견한 문제·확인 근거·실행 방법·비용과 기간·확인 지표)
public/app.js         화면 (첫 화면 → 가게 확인 → 인터뷰 → 완료)
public/               index.html, styles.css, 로고
site/                 robots.txt, sitemap.xml, 네이버·구글 소유확인 파일
scripts/build-site.mjs  public/ + site/ → dist/ (Vercel 빌드)
scripts/dev.mjs       로컬 개발 서버 (화면 + /api)
tests/api.test.mjs    서버 함수 점검 (가짜 AI·저장소)
tests/questions.test.mjs  인터뷰 분기 점검 (메뉴 이름 재사용, 배달 생략, 비용 모름 안내, 질문 수)
tests/solutions.test.mjs  솔루션 점검 (손님 앞 식사·영업 중 청소·담요·잔반·비용 기록)
tests/research.test.mjs   인터넷 조사 점검 (열 수 있는 사이트 제한·결과 정리·캐시·운영/미리보기 차이)
tests/report.test.mjs     보고서 점검 (계산값·수수료 이중 차감·입력 검사·결과 정리·캐시·중복 요청 잠금·형식 고치기·한도)
```

## 비용과 이용량 관리

- AI는 가게 찾기(1곳 약 $0.11~0.12)와 보고서 만들기에 씁니다. 인터뷰 질문은 브라우저에서 규칙으로 만들어 추가 비용이 없습니다.
- 인터넷 조사는 호출 전에 $0.45를 잡아둔 뒤 실제 비용으로 정산하고, 같은 가게는 3일 동안 저장한 결과를 씁니다(답변을 바꿔 보고서를 다시 만들어도 조사는 다시 안 함).
- 보고서 단계는 웹 검색 없이 만들고, 호출 전에 $0.25를 잡아둔 뒤 실제 비용으로 정산합니다. 같은 답변은 서버에 24시간 보관한 보고서를 돌려주고(비용 없음), 같은 보고서를 만드는 중이면 두 번째 요청은 AI를 부르지 않고 기다립니다(중복 비용 방지).
- 호출 전에 최대 예상 비용($0.35)을 하루 예산에서 잡아두고, 끝나면 OpenRouter가 알려준 실제 비용으로 정산합니다.
- **이용량 제한은 기본으로 꺼져 있습니다**(운영자 요청, 2026-11-09). 위 환경변수에 값을 넣으면 그때만 하루 예산·방문자별 횟수를 넘을 때 AI를 부르지 않고 안내합니다(한국 시간 기준 날짜). `0`·`off`는 제한 없음.
- 제한이 없으면 OpenRouter 잔액이 실제 상한입니다(자동 충전이 꺼져 있으면 잔액이 떨어질 때 AI_CREDIT 안내가 나옵니다). OpenRouter 키 설정에서 키별 사용 한도를 걸 수도 있습니다.
- 같은 상호명·주소는 3일 동안 캐시해서 다시 비용이 들지 않게 합니다.
- `Origin`이 같은 주소인 요청만 받고, OpenRouter 요청에 `provider.data_collection: deny`를 넣습니다.
