# 매출올려드림 AI · 첫 구현 설계서 (데모 모드)

> "우리 가게, 매출이 달라질 방법을 찾다! 질문에 답하면 가게를 분석하고 매출과 수익을 개선할 방법을 알려드립니다."

가게를 진단하고 **우선 해결할 문제 3가지 · 이번 주 할 일 · 효과 확인 방법**을 보고서로 돌려주는 웹서비스의 첫 버전입니다.

## 1. 공개 사이트와 배포

- 주소: https://www.kkumsu.com/ (Vercel 프로젝트 `kkumsu`, GitHub `whdvy77796-cell/kkumsu`의 `main` 브랜치)
- Vercel이 `npm run build`(`scripts/build-site.mjs`)로 `dist/`를 만들어 배포합니다: 단일 HTML + robots.txt + sitemap.xml + 네이버·구글 소유확인 파일(`site/`).
- 공개 사이트는 **브라우저 저장판**입니다. 입력한 매출·비용·사진은 서버로 보내지 않고 사용자의 브라우저에만 암호화해 저장하므로, 다른 기기에서 이어하기는 되지 않습니다.
- `server/`의 서버판은 저장소에만 있고 배포하지 않았습니다. 다른 기기 이어하기가 필요하면 암호화 저장소(DB·파일 저장)를 연결한 뒤 배포해야 합니다.
- 이전 사이트(인소서와 꿸수 파일)는 브랜치 `archive/insosoe-kkumsu-20261108`에 그대로 보관했고, 인소서 개발 브랜치들도 지우지 않았습니다. 되돌리려면 보관 브랜치의 파일로 main을 되돌리면 됩니다.

**설치 없이 체험:** `매출올려드림AI_체험판.html`을 더블클릭하세요. 서버 없이 이 브라우저(IndexedDB)에만 암호화해 저장합니다.

```
start.cmd                 (윈도우: 더블클릭)
```

환경 변수: `PORT`(기본 5180), `HOST`(기본 127.0.0.1), `DATA_DIR`(기본 `./data`), `MAECHUL_SECRET`(32바이트 base64, 없으면 `data/.server-secret` 자동 생성).

## 3. 설계 핵심 ① 질문의 깊이

- **질문 은행 126개** (14개 영역, 63개는 조건부). 모든 사람에게 같은 질문을 던지지 않고 업종·판매 비중·답변·고민에 따라 보여줄 질문을 계산합니다(`shared/engine.js`).
- **순서:** 운영 형태 → 목표·제약 → 매출 → **사장님이 고른 고민과 관련된 영역 먼저** → 나머지 → 재확인. 고민과 관련된 영역은 심화 질문까지 묻고, 나머지는 핵심 질문만 묻습니다("자세히 답하기"로 확장 가능).
- **답변에 따른 추가 질문 (기획서 예시 반영):**

| 답변 | 이어지는 질문 |
|---|---|
| 월매출 입력 | 어느 달 기준? 결제금액/입금액/혼합? |
| 배달 비중 10% 이상 | 배달 주문 수·1건 결제금액·중개/결제 수수료율·가게 부담 배달비·할인·포장비, (입금액 기준이면) 이미 빠졌는지 |
| 메뉴 25개 이상(카페 30개) | 잘/안 팔리는 메뉴, 한 메뉴 전용 재료 |
| 광고비 > 0 | 어디에 얼마, 주문·예약으로 이어졌는지 확인하는지 |
| 단골 비중 답변 | 기록인가 체감인가 |
| 재료 폐기 가끔/자주 | 어떤 재료를, 얼마나, 왜 |
| 가격이 더 비쌈 | 이유 먼저 (재료·양·수작업·공간·비용) |
| 카페 | 체류시간·노트북 손님·원두 사용량/단가·디저트 조달·폐기·동반 구매율 |
| 매장 손님 20% 미만 | 매장 환경·화장실 질문 생략 |

- **모르는 값:** 숫자 질문마다 "정확히 모름 / 대략 입력 / 해당 없음 / 나중에 답하기". 모름은 0원이 아니라 "추가 확인 필요"로 기록합니다.
- **재확인 질문(자동 생성):** 월매출 ≠ 주문 수×객단가(25% 이상 차이), 배달 비중 ≠ 배달 주문 금액, 식재료비가 매출의 70% 초과·10% 미만, 직원 1명당 인건비 이상값, 메뉴 판매량 합계 과다, 매입 품목 합계 > 식재료비(예: 30과 300), 공개 정보와 답변 불일치. 확인 전에는 관련 해결책의 확실성을 낮추고 보고서 맨 위에 "먼저 확인해 주세요"로 표시합니다.

## 4. 설계 핵심 ② 비교 자료의 정확성

- **같은 기간·같은 기준:** 주·년 단위 금액은 월로 환산(1주 × 4.35, 1년 ÷ 12). 매출이 입금액 기준이면 이미 빠진 카드·배달앱 수수료를 비용에서 다시 빼지 않고, 기준을 모르면 두 경우를 모두 계산해 **범위**로 보여줍니다.
- **누락 비용:** 빠진 비용이 있으면 이익을 "입력된 비용만 뺀 금액(실제 이익은 이보다 적음)"으로 표시. 모두 있으면 "입력 자료 기준 추정 이익". "확정 순이익"이라는 표현은 쓰지 않습니다. 대표자 인건비 포함 여부, 부가세·소득세·대출 상환 미반영을 함께 표시합니다.
- **공개 통계는 참고만:** 「2025 외식업체 경영실태 조사 보고서」(농림축산식품부·한국농촌경제연구원, 2024년 실적, 표 3-16-1) 업종 평균 — 일반음식점 식재료비 40.9%·고용인 인건비 14.2%·임차료 7.1%, 비알코올 음료점업 38.9%·15.9%·8.5%, 한식 41.2%·14.0%·6.9%. 이 조사의 영업이익은 대표자·가족 인건비를 뺀 값이라 "사장님 몫 포함 금액"과 직접 비교하지 않습니다. 최저임금: 2026년 10,320원, 2027년 10,700원(고시).
- **메뉴 원가 vs 실제 구매:** 메뉴별 원가×판매량으로 만든 이론 원가율과 실제 구매 비율의 차이(5%p 이상)를 재료 누수 신호로 씁니다(원가를 아는 메뉴가 판매량의 40% 이상일 때만).
- **매입가 비교 규칙:** 품목·브랜드·규격(양×입수)·등급/원산지·부가세·배송비가 모두 같고 30일 이내 확인한 견적만 "같은 조건 비교" → 이때만 월 예상 절감액 계산. 규격이 다르면 "참고 비교(단위가격 환산만)", 무게와 개수처럼 단위가 다르면 "비교 불가". 부가세 별도 가격은 10%를 더해 맞추고, 배송비는 주문 횟수로 나눠 단위가격에 넣습니다. "다른 사장님보다 비싸다"는 표현은 쓰지 않습니다.
- **주변 가게:** 메뉴 이름이 같아도 양·구성이 같을 때만 같은 조건 비교. 출처·확인 날짜 기록, 매출·원가 추정 금지.
- **외부 정보:** 가게명과 주소가 모두 일치한다고 확인된 항목만 사용(동명이점 제외). 확인하지 못한 채널은 "캡처를 올려주세요"로 요청. 공개 페이지·리뷰 속 문장은 분석 자료로만 취급.
- **파일 추출:** CSV에서 날짜·금액·취소 열을 자동으로 찾고, 월별 합계·결제 줄 수·요일별 합계를 보여준 뒤 **사장님이 숫자를 고치고 "확인했어요"를 체크해야** 반영합니다. 배달앱 매출이 빠진 파일은 월매출로 쓰지 않고 참고 자료로만 보관합니다. 20일 미만 기록 달은 "부분 기록"으로 표시합니다.

## 5. 설계 핵심 ③ 실행 계획의 구체성

- **해결책 한 개 = 6요소:** 발견한 문제 / 판단 근거(사장님 답변·자료에서 확인·계산 결과·개선 가설·추가 확인 필요 표시) / 추천 행동 / 필요한 비용·시간·담당 / 기대 효과(매출 개선과 수익성 개선 구분)와 불확실성 / 효과 확인 방법(지표·방법·기간·지금 값).
- **우선순위 점수 공개:** 영향도(1~3) × 근거 확실성(1~3) × 실행 가능성(1~3) + 고민 관련 영역 +3 + 원하는 변화 일치 +2. 상위 3개는 영역이 겹치지 않게 고르고, 사장님이 매출·수익성을 모두 원하면 한쪽으로만 쏠리지 않게 조정합니다.
- **예산·시간 제약:** 예산(1만 원 이하 ~ 300만 원 이상)과 주당 시간(1시간 미만 ~ 5시간 이상)을 넘는 해결책은 작은 대안으로 바꿔 제시하고(예: 입간판 대신 A4 창문 메뉴판, 스탬프 대신 계산대 노트), 대안도 어려우면 이유와 미루는 방법을 알려줍니다.
- **실행 계획:** 이번 주(주당 가능 시간 안에서) / 2~4주 / 1~3개월. 체크 표시 저장, 효과 확인 기록표 CSV 내려받기.
- **금지:** 근거 없는 "매출 30% 상승 예상", 근거 없는 매장 점수, 정보가 없다는 이유의 감점, 판매량만 보고 메뉴 삭제 권유, 세제 종류만으로 청결 평가, 인테리어 설치만으로 매출 상승 단정.

## 7. 개인정보·보안

- 회원가입 없이 **이어하기 링크(무작위 32바이트 토큰)**로만 열람. 토큰은 URL의 `#` 뒤에 있어 서버 로그·Referer로 전달되지 않고, 서버에는 HMAC 해시만 저장.
- 저장 데이터와 파일은 **토큰으로 만든 열쇠(HKDF-SHA256)로 AES-256-GCM 암호화**. 서버 비밀값만으로는 열 수 없고, 링크를 잃으면 복구할 수 없습니다(화면에 안내).
- 링크 재발급(예전 링크 즉시 무효, 파일 재암호화) · 전체 삭제(가게 이름 입력 확인) · 이 기기 목록에서만 지우기.
- 파일은 확장자가 아니라 내용으로 형식 확인(JPG·PNG·WEBP·HEIC·PDF·CSV), 10MB·30개 제한. CSP·nosniff·no-referrer·no-store, 인증 실패 횟수 제한, 폴더 밖 경로 차단, 동시 저장 충돌 감지(409).
- **운영 전 필요:** HTTPS, 비밀값 관리(KMS 등), 백업·복구 정책, 접근 로그 정책, 개인정보 처리방침, 이메일 발송, 실제 AI 사용 시 처리업체 고지·동의.

## 8. 완성 기준 확인 (`npm test`)

| 기획서 완성 기준 | 확인 내용 |
|---|---|
| 배달 중심 음식점·홀 중심 카페의 다른 추가 질문 | 배달 질문 6종은 음식점에만, 체류·노트북·원두·디저트 질문은 카페에만. 답변별 추가 질문 9종 등장/미등장 |
| 모르는 비용을 0원 처리하지 않음 | 인건비 "모름" → 누락 표시, 이익은 상한값 라벨, 인건비율 미산출 |

| 각 해결책에 근거와 효과 확인 방법 | 모든 해결책 6요소 존재, 상승률 예측 문구 없음 |

서버 테스트: 토큰 없이는 401, 저장 파일에 가게 이름 평문 없음, 409 충돌, CSV 추출(취소 제외), 잘못된 파일 415, 재발급 후 예전 링크 401, 삭제 후 폴더 없음, 화면 파일·보안 헤더·경로 차단.

## 9. 다음 단계 제안 (승인이 필요한 일)

1. **AI 연결:** 계산 결과(JSON)만 넘겨 해석·설명 문장을 다듬고, 숫자는 원래 값과 대조 검증. 사진 판독은 "사진에서 확인한 점"을 확실성과 함께 제안하고 사장님 확인 후 반영. API 비용·처리업체 고지 필요.
2. **검색 연결:** 네이버 검색 API(지역), 농산물 시세(KAMIS) 등. API 키·이용약관·호출 한도 확인 필요. 결과는 출처·날짜와 함께 "자료에서 확인"으로만 사용.
3. **배포:** HTTPS 호스팅 + 암호화 저장소 + 이메일 링크. 실제 사장님 3~5명 시범 사용으로 질문 길이와 보고서 이해도 확인.
4. **가격·결제:** 무료 기본 진단 범위와 건당 상세 보고서 가격 결정 후, 시작 화면에 먼저 안내.
